# changelog

## 0.0.15

- the routing rules are rewritten around one output invariant, done means collected and verified, and come out roughly half the length; the codex row now requires synchronous execution inside every codex brief, same turn collection through fusion:job-collector naming the codex companion's status and result commands, a heartbeat rule against silent polling turns, and receipts and truncation merged into one non deliverable rule; escalation ladders and the circuit breaker table move out to a new plugins/fusion/rules/troubleshooting.md so the live rules stay lean while the reference material is still one read away
- new session scoped codex jobs monitor (plugins/fusion/scripts/codex-jobs-monitor.mjs, wired through plugins/fusion/monitors/monitors.json): jobs are scoped to the current workspace via the git root, failed and cancelled lines gain an errorMessage suffix, and a running record whose driving process has vanished is reported once as died instead of forever
- fusion:job-collector's contract narrows to foreground only polling; its final message is always the collected result or a collector timeout line, never a background handoff
- grok-rescue and the grok cli runtime skill stop passing --background on their own initiative; it is reserved for briefs that are explicitly watch style, with a documented recovery procedure for a stray flag
- test suite grows to 144 with a dedicated suite for the codex jobs monitor (session scoping, error suffixes, died detection)

## 0.0.14

- the background job monitor is session scoped: each session's monitor now emits only jobs whose recorded claude session id matches its own CLAUDE_CODE_SESSION_ID (verified injected into monitor processes), fixing live cross session noise where every session in a workspace heard every other session's completions; it degrades to workspace wide reporting when the env var is unavailable, absorbs pre existing terminal jobs regardless of owner, survives transient registry races (the per tick scan is exception proof, since claude code never restarts a crashed monitor), handles SIGHUP, and its line no longer tells the orchestrator to reflexively run /grok:result, motivated by a live monitor death (exit 144) and a user hitting the cross session leak within a day of 0.0.13
- collection is itself delegated: new fusion:job-collector agent (haiku, one detached bash loop polling a supplied status command until a terminal marker, then returning the result command output verbatim, with a collector timeout line on cap); the routing rules route codex background collection and timeout reruns through it, ban the main loop from touching companion state for any job a rescue agent owns, and mark session monitor lines about agent owned jobs as informational, motivated by live sessions with 43 main loop polls including a hand written 60 iteration codex loop
- routing rules additions: parallel packages must declare each other's files as intended in flight changes and never revert or clean anything outside their own list (a worker treated a sibling package's uncommitted work as drift and destroyed it), and the user facing quality floor now states that generated content deliverables are verified by reading the actual produced artifact, not by a passing verification command alone, motivated by a live session where a deployed fix still produced an off topic llm reply
- test suite grows from 127 to 130: session scoped emission (matching, mismatching, env unset) and the vanished jobs directory resilience case

## 0.0.13

- question policy: the routing rules gain a whitelist for what may reach the user as a question (product and design tradeoffs, hard to reverse actions, decisions the user reserved); execution mechanics questions are banned outright, motivated by live sessions where /grok:review interrupted every run with "background or wait?" and every review ended with "which findings should be fixed?"; review findings are now triaged by verification instead (confirmed ones dispatched for fixing without a prompt, false positives dropped with a stated reason, one fixed/dropped/why report), and surviving questions batch into one prompt
- every dispatch is a background subagent: /grok:review rides a new grok-review-runner agent (haiku, single background bash call, 30 minute companion timeout), /grok:task and /grok:best-of-n forward through grok-rescue, and grok-rescue itself launches the companion with run_in_background plus the raised timeout so long runs stop dying at the foreground bash cap; detached --background jobs are reserved for watch style work and explicit user requests; the escalation ladder now diagnoses the brief against the dispatch gate before blaming the engine, since a starved worker looks exactly like a weak one
- commands migrate to the skills layout: all 14 slash commands move from the legacy commands/ directories to skills/<name>/SKILL.md with invocation names unchanged; panel and ultra split their long descriptions into description plus when_to_use, trimming the skill listing budget
- stop gate becomes a plugin setting: plugin.json declares a stop_gate userConfig boolean, the companion honors CLAUDE_PLUGIN_OPTION_STOP_GATE with precedence over the legacy flag (true/1 enables, false/0 disables, garbage and unset fall back), and /grok:setup keeps the CLI flags as the scripting fallback
- background job monitor: a monitors/monitors.json entry runs jobs-monitor.mjs for the session, which absorbs pre existing terminal jobs silently and then emits one line per job newly reaching done, error, or cancelled with the failure kind and a /grok:result hint; interactive sessions now hear about detached job completions without polling, while the companion contract keeps collection via status and result as the reliable path
- marketplace and manifest modernization from a full docs audit: top level description and version replace the metadata block, both manifests gain $schema, displayName, homepage, repository, keywords (plus category and tags per marketplace entry), ci adds claude plugin validate --strict, the readme floor rises to claude code 2.1.198 (the dispatch flow relies on background subagents being the default), forwarder agents declare background: true, and the stop gate hook gains a statusMessage
- test suite grows from 118 to 127: stop gate env precedence (true, false, garbage fallback, unset) and the jobs monitor (no history replay, single line per transition, failure kind reporting, sigterm exit, missing directory tolerance)

## 0.0.12

- dead process detection in the grok companion: status, result, and cancel verify the driving process before trusting a running record; a dead process is persisted as failure kind died with the check re-run under the record lock (a racing completion or pid write survives, found by cross engine review), a record with no recorded pids gets a launcher grace window (default 15000ms, GROK_COMPANION_PIDLESS_RUNNING_GRACE_MS) after which it is treated as died, EPERM counts as alive, and terminal records are now fully immutable; motivated by a live session where a peer background job died silently twice while its status reported running for 20 minutes
- routing policy generalizes the incident into engine agnostic principles: a running status from any background executor is a claim to verify rather than trust (the grok companion now checks itself; codex is checked via ps and its rollout file), died joins the circuit breaker table (cancel, one resume with the failure attached, escalate to a different executor on a second silent death), and rotation discipline extends to every warm peer thread including codex resume since oversized threads are the ones that die mid stream
- docs/companion-contract.md becomes the single canonical companion contract (job lifecycle, liveness, rendered outcome lines, failure kinds, background collection, resume-last selection, stop gate verdicts); docs/grok-contract.md is demoted to the grok instance keeping only CLI specific facts, and the readme drops the hardcoded two peer world view for an open engine set with grok and codex as current instances
- generality batch from an eight facet fleet audit: nested CLI deny rules generate from one exported name list, fusion stats gains a provider registry and file engine descriptors so an engine section is one data entry, ci json validation derives from globs with empty glob guards, the bench codex version probe reads the real plugin cache instead of a nonexistent path, bench redaction becomes a data driven rule registry, worker agent frontmatter stops naming peer engines so routing has one source of truth, and /grok:stats and /fusion:stats agree on the mean wall clock label
- the audit's over generalization verdicts are recorded as deliberate non changes: no shared companion core, no cross plugin doctrine imports, and no n condition bench schema until a second hosted engine or third measured condition exists, keeping marketplace plugins self contained
- test suite grows from 103 to 118 and the companion test scaffolding dedupes into tests/lib/companion-harness.mjs and tests/lib/git-fixture.mjs with per file behavior preserved (71 tests before and after across the nine refactored files)

## 0.0.11

- grok companion contract hardening: cancelled jobs now persist status cancelled and emit state: cancelled with failure: cancelled everywhere (previously failJob wrote state: error even for cancellations, breaking the parseable outcome contract); quota and rate limit patterns match before auth so mixed stderr like "quota exceeded, login required" classifies as quota; a zero exit run with a malformed json envelope is recorded as failure: error with a bounded stdout tail instead of done; pre run errors (bad --prompt-file, bad --cwd) emit parseable state and failure lines too
- job state is now crash and race safe: records write through temp file plus rename under a lock, terminal states never regress, and a success that lands after a cancel was requested finishes cancelled instead of done (locked check and set on cancelRequestedAt, found by cross engine review); cancellation and SessionEnd cleanup escalate SIGTERM to SIGKILL with exit verification instead of fire and forget
- consult mode is hardened and documented: the allow list now denies shell chaining, redirection, backticks, and dollar expansion (the installed grok CLI matches bash rules by prefix, so wildcard allows were bypassable with compound commands); consult briefs must instruct file reads only, written into grok-prompting and the rescue agent so orchestrators stop learning it from failure: permission at runtime
- routing policy learns from a live fleet session: codex background jobs are collected by the main loop (/codex:status, /codex:result), a forwarder agent returning only a "task started" line is not a truncated run and resuming it is futile by contract, and the escalation section gains quality driven escalation (a completed run can still fail review; correct but substandard output re-dispatches one rung up with critique attached, judging the output not the price tag)
- orchestration.md restructured for llm compliance: implementation routing and failure kinds become tables, dispatch becomes a numbered procedure, routing gains an explicit priority order (correctness and safety, then user facing quality, then latency, then cost) and a user facing quality floor (ui, copy, api design, docs, and naming need a taste review before acceptance); subscription economics framing replaced with availability aware language, model names moved out of load bearing sentences
- user scoreable engine capability table: /fusion:config now edits ~/.claude/plugins/data/fusion-claude-code-fusion/model-routing.json (intelligence, taste, cost, 1 to 5 per engine) via the new fusion-config.mjs, and rules sync renders the scores into a sentinel region of the live rules; drift detection becomes template aware (manifest format 2 hashes with the generated region normalized) so scored live rules are never mistaken for hand edits, an invalid routing file fails closed keeping the current live table, and /fusion:doctor and /fusion:setup compare template hashes instead of raw bytes
- agent descriptions align with routing: trivial-worker and fast-worker describe themselves as fallback and tool surface lanes so auto delegation cannot prefer them over the grok and codex primary lanes; /fusion:stats is documented as peer delegation history (not the full engine mix); doctor reports effort and maxTurns alongside model and checks the codex job state directory
- bench harness can no longer publish misleading numbers: failed runs write records instead of disappearing, env.json captures plugin and cli versions, the task manifest hashes every file in a task (fixtures, mutants, hidden verifiers) instead of just brief and verify, B1 setup actually excludes peer plugins, summarize computes the claimed comparisons (C1a, C1b, C2) with billed token totals and prints not measurable where data is missing, zero delegation B runs are flagged invalid for claims, and the publication gate requires the full 8 to 12 task suite
- test suite grows from 60 to 103: quota and generic error failure kinds, validateReviewOutput and parseArgs units, fusion-stats with a live grok path, model table rendering and drift, the cancel race, stop gate first line parsing, and bounded output; ci adds macos, json manifest validation, and bench manifest freshness (node bench/manifest.mjs --check)
- docs catch up: readme lists /fusion:ultra and /fusion:config in the layout, GROK_CONSULT_ALLOW joins the documented overrides, SECURITY.md states that briefs are not redacted and secrets must never enter peer briefs, the unused review-output.schema.json is deleted in favor of validateReviewOutput as the canonical review contract, and grok-cli-runtime documents the real flag surface

## 0.0.10

- model aware peer lanes: codex is now the primary implementation lane (the current GPT 5.x flagship, spec grade briefs with explicit completion criteria, output contract, boundaries, and a verification command); grok is the quick turnaround lane (Composer 2.5 Fast by default) for small fixes, drafts, research digests, and large context reads; trivial single file tasks now default to grok, with fusion:trivial-worker as the fallback
- new /fusion:config command reads local model configuration across engines, enumerates available models, and changes defaults interactively
- /fusion:ultra facet routing: codex takes implementation and adversarial facets with spec grade briefs; grok takes high volume facets, research digests, and scoped fixes
- /fusion:doctor gains a peer engine defaults check (model keys from each CLI config, never the full files) and points at /fusion:config and `grok models` for remediation
- the codex prerequisite is explicit: codex@openai-codex powers the implementation lane, the rules document per call model and effort overrides (including the spark alias) and the fallback routing when the plugin is absent, and /codex:adversarial-review becomes the named cross engine review command

## 0.0.9

- rules sync is automatic: a SessionStart hook compares the installed ~/.claude/rules/orchestration.md against the plugin's canonical copy and a manifest of every released version's hash; a missing file is installed, a file matching any released hash is safely updated (provably never hand edited), and unknown content is never touched, with a one line notice pointing at /fusion:setup to reconcile. /fusion:setup narrows to first install permission checks and local edit reconciliation, and a guard test fails the suite when the rules change without regenerating the manifest
- routing policy gains the pre dispatch side: classify the user's message before any dispatch (questions and problem descriptions are handled in the main loop with read only tools, executors go out only for actual change requests); reconnaissance and execution are two dispatches on unfamiliar surfaces; and the verification command becomes the dispatch gate, with the main loop owning what to do and how to verify while the worker owns how to implement

## 0.0.8

- routing policy: worker reuse is scoped and rotated. a follow up goes to the same worker only when it touches the same files or surface as its previous brief; new packages, different surfaces, and parallelizable work get fresh agents; after about three follow up resumes or when notifications show usage nearing the context window, rotate to a fresh worker whose brief carries the accumulated decisions (observed live: one ui worker reached 78 percent of its window after five follow up resumes). truncation resumes count toward rotation and the same discipline applies to grok --resume-last threads

## 0.0.7

- worker turn caps are runaway breakers, not task size estimates: fusion:fast-worker goes from 30 to 120 turns and fusion:deep-reasoner from 40 to 80, after four fast-worker packages in one day exhausted the 30 turn cap mid implementation and their dangling progress narration was reported as the final result; fusion:trivial-worker stays at 15 by design, since exhausting it means the task was routed wrong
- routing policy: truncation is not completion. a worker result that ends in forward looking narration or lacks the verification output its brief demanded is treated as a truncated run and resumed with SendMessage to finish and re-report, instead of being read as a final report
- public benchmark scaffolding: bench/METHODOLOGY.md defines the claims under test (C1a Claude tier quota displacement, C1b peer offload increment, C2 wall clock compression, C3 typed failure surfacing scoped to the tested grok contract) with condition isolation, pre registered task manifests, verifier isolation with mutant self tests, a fixed exclusion enum, and a publication gate; the draft went through a blind two engine adversarial panel and every blocking finding was folded in
- the harness ships alongside it: run.mjs (isolated CLAUDE_CONFIG_DIR per condition, verifiers run outside the model visible worktree, token accounting by model and role from transcripts), a strict run record schema, summarize.mjs (pass matrix, median and IQR, refuses to compare snapshots from different task manifests), manifest.mjs (content hashed task registration), redact.mjs (path and credential scrubbing), and the first task T01-seeded-bug with a mutant self test; 12 new tests, suite at 60
- no results are published yet and the README says so: the task pool holds 1 of the planned 8 to 12 tasks, so no snapshot passes the methodology's own publication gate; in tree results stay lean (runs.jsonl, env.json, summary) with full redacted transcripts attached to releases instead of committed to the tree

## 0.0.6

- permission failure kind: a consult mode run whose tool call fell outside the allow list was reported as done with empty or partial output, because the grok CLI cancels the whole turn and exits 0 with stopReason Cancelled; the companion now detects that shape across the foreground, background, review, and stop gate paths and converts it to state: error, failure: permission with guidance to re-dispatch with --write or rewrite the brief (observed live: research briefs calling gh api died silently twice in a row)
- consult mode allow list gains read only gh subcommands (pr view/list/diff/checks, issue view/list, repo view, search, run view/list, release view/list); gh api stays write mode only since it can send mutating requests with the user's credentials
- GROK_CONSULT_ALLOW appends comma separated extra allow rules to consult mode per machine; deny rules still beat them and write mode ignores the variable
- routing policy: permission does not break the engine in the circuit breaker; re-dispatch the same brief once with --write when repository changes are acceptable, otherwise rewrite the brief to avoid shell commands

## 0.0.5

- the routing policy is rewritten around an operating model: the orchestrator runs the session like a founder with a paid bench, biases to fan out (five or more concurrent delegations is a normal state, under dispatching is the failure mode), keeps every engine drawing, and trusts then verifies instead of hovering; grok is named the fast lane and codex the deep lane
- peer engagement policy: peers are executors, not just reviewers. plans with three or more independent packages route at least one to a peer, multi source research fans one track to a peer by default, and a per session balance check shifts the next eligible package to an idle peer (motivated by observing sessions where codex and grok barely participated while claude workers took everything)
- auto invocation: the panel and the new fleet fire from plain language, not only a typed slash command. /fusion:panel's description is trigger shaped, and a new rules section maps natural language moments to both without the user typing a slash
- /fusion:ultra: the peer engine answer to ultracode. asking to go deep, thorough, or exhaustive fans the work out as a fleet of parallel Grok and Codex agents (6 to 8 facets by default, up to about 12), billed to their own subscriptions, then synthesized into one deliverable; a size gate skips the fleet for small tasks
- /grok:task gains --web, which re-enables grok's web tools for research briefs (they stay disabled for code work); grok-rescue's description now claims implementation packages and research digests first instead of introducing itself as a second opinion

## 0.0.4
