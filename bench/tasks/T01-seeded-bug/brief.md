The small library in this folder is a TTL aware LRU cache exported from index.js. After inserting keys until the cache is at capacity, reading one key and then inserting another key should drop the key that was not read, while the key that was read should remain. With maxSize 2, if I set a to 1, set b to 2, get a, then set c to 3, has(a) and get(a) should still work and b should be gone. In the current code, a disappears and b stays, so the eviction order does not match LRU behavior. The same wrong pattern shows up when maxSize is 3 and I touch one key several times before adding a new key: the hot key is evicted instead of a cold one. Please fix the implementation so capacity eviction follows least recently used order while keeping TTL expiry and the existing public API unchanged.
